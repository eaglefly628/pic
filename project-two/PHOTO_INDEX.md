# 家庭影像索引与安全整理

`scripts/photo_index.py` 是面向 Samba/NAS 大型影像库的第一阶段索引器。

- 只读取目录项和 `stat` 元数据，不读取图片像素或视频内容。
- 不创建、移动、重命名或删除源目录里的任何文件。
- SQLite 索引保存在本机；每 100 个目录项提交，支持暂停和续跑。
- 扫描未完整完成时绝不把未看到的文件标记为缺失。
- 第一阶段只按扩展名区分图片、视频和 sidecar，并按路径名称标记截屏/录屏候选。

正常使用不需要手动运行脚本：先在 Finder 挂载 Samba 目录，再从项目入口
`http://localhost:5180/#gallery` 打开家庭影像，在导入页点击“开始扫描”。页面可查看进度、
安全暂停和继续扫描。直接打开 `file://` 页面无法使用本机扫描服务。

开发排错时也可直接执行 `python3 scripts/photo_index.py status` 查看最近状态。

默认索引位置：

`~/Library/Application Support/我家里的一切/photo-index.sqlite3`

默认排除 `TimeMachine`、文档、音频及工作目录；可重复传入 `--exclude` 增加规则。

## 新备份目录的定向增量扫描

其他程序向 S300 写入新备份后，先等备份完成，再**只扫描明确指定的备份目录及其子目录**；
不因新增约 3,000 张照片就重扫整个 `家庭影像库`。2026-10-13 本轮指定：

- `来自iPhone的相册备份/`
- `来自iPhone的视频备份/`

使用 `scripts/scan_selected_backup_dirs.py`，源根仍是 S300 挂载点 `$HOME_PHOTO_SOURCE`，
两个目录以相对路径传入 `--include`。它把新文件增量加入同一份本机索引；同路径文件
按大小和修改时间更新，不复制、移动或删除原件，也不把未扫描的其他目录标成缺失。
扫描中断后可再次运行同一命令复查这两个目录。新增媒体的时间、地点分析及后续归档
是独立步骤；新备份不会自动进入年月目录或自动参与删除去重。

```bash
python3 scripts/scan_selected_backup_dirs.py "$HOME_PHOTO_SOURCE" \
  --include '来自iPhone的相册备份' \
  --include '来自iPhone的视频备份'
```

应用的“导入”和“索引报告”页会列出 S300 顶层名称含“备份”的可读目录。勾选目录后，
“扫描所选备份目录”只遍历这些目录及其子目录；“全盘复查”才遍历整个来源。页面显示
本轮新增照片、视频及目录进度，扫描中可安全暂停，并以相同目录从断点继续。不能与
时间地点分析或整理任务同时运行。后台只接受已挂载 S300 中真实、可读的备份目录，
排除应用自己的索引备份目录，拒绝任意路径和符号链接。`._` 开头的 macOS 附属文件
不计作照片或视频。未选择的目录不做缺失对账；同一路径再次扫描会更新变化的文件，
不会复制原件。

扫描完成后，按页面的“待分析媒体”数量运行时间地点分析；仅处理尚未分析或文件大小、
修改时间已变化的媒体。然后查看“库外待归档”数量，生成**新增文件整理预演**；可信时间项
经确认后同卷移动，其余继续留在原处。第一轮完成后，页面提供**待确认项预演**，按一致的
月份线索、仅年份线索和无法归类三类列出目标，再经单独确认后整理。新备份不会自动移动或
删除；归档后的重复检测另行发起。旧的“分析已完成／整理已完成”记录不能遮盖新媒体待处理数量。

## 按时间整理

时间与地点分析完成后，可在“索引报告”生成整理预演。整理阶段有以下硬性保护：

- 可信时间进入 `家庭影像库/YYYY/YYYY-MM/`；文件名增加 `YYYYMMDD-HHMMSS__` 拍摄时间前缀，
  因而在 Finder、Windows 和 NAS 中按名称排序就是时间顺序。低可信或异常时间只生成
  `家庭影像库/_待确认时间/` 建议，第一轮原地保留，避免误拆软件素材或来源目录。
- 只允许在同一挂载卷内逐文件原子移动，不做一份占用约 550 GiB 的完整复制。
- 同名目标使用稳定的来源路径摘要后缀，绝不覆盖；Live Photo 图片、视频和 sidecar
  作为一组进入同一目标月份目录。
- 每移动一个文件就核对大小并同步更新 SQLite。中断后会核对源与目标的实际状态再续跑。
- 不合并重复内容、不自动删除旧目录；完成后自动生成并上传新的 SQLite 一致性快照。

开发测试可运行：

`python3 scripts/test-photo-organize.py`

## 在其他电脑上一键接力

索引数据库包含照片路径、拍摄时间和 GPS，不能明文提交到 GitHub。正常使用不需要运行
PowerShell 或 Python 命令：在家庭影像侧栏打开“其他电脑一键接力”。

1. 在当前电脑安全暂停扫描、分析或整理任务，点击“一键准备接力”。应用使用
   自己正在运行的 Python 环境制作 SQLite 一致性快照，并把接力包保存到 S300 的
   `我家里的一切-接力` 目录。
2. 在另一台电脑把同一个 S300 映射或挂载好，拉取最新代码并启动应用，进入同一菜单，点击
   “一键接力并继续”。应用先校验 SHA-256 和 SQLite 完整性，再备份本机现有索引、
   导入扫描/时间地点/整理进度，并把旧电脑路径重绑定为当前挂载路径。
3. 导入完成后直接打开“索引报告”继续工作。若本机已有相同任务且进度更新，旧接力包不会
   覆盖新进度。

任意时刻只允许一台电脑执行整理。接力包不含照片、视频或家庭密码。S300 目录中的 Windows
批处理仍作为应用无法启动时的备用入口，不再是正常工作流。

## 照片浏览与 S300 缩略图

按时间和地点浏览是同一份 SQLite 索引上的两种查询视图，不为地点再复制一套原片或创建实体目录。
例如“日本”可汇总不同年份的照片；选择某个月则可展开该月的地点。列表按页查询元数据，
只为当前可见的项目请求缩略图；点开照片才从 S300 读取原图。浏览器和本机可以保留临时缓存，
但不在本机长期保存完整缩略图库。

2026-10-09：图库、时间、地点、离线地图和事件候选已接入同一本机 SQLite 索引。
图库和时间轴按实际 `家庭影像库/YYYY/YYYY-MM/` 目录分页；仅确定年份和未能归档单列，
不会把旧索引的月份占位日显示为真实拍摄日。选中月份可按时间、名称或大小排序。
地点按约 0.1° 的 GPS 坐标分组，排除 0,0 等无效坐标；离线 GeoNames 城镇数据已为
634 个地点簇保存附近地名，但这不是街道级地址。页面直接显示地名，不再把经纬度和地点叠在一起；
没有离线地名的簇显示“地点待命名”。
地图默认显示 Natural Earth 的离线世界陆地底图，可缩放和拖动；在线街道底图由用户选择加载。
事件按可信具体日期形成待命名分组。当前页的网格缩略图和视频封面按需生成并缓存到 S300；
点开单张照片才生成更大的预览。浏览时可把照片及同名 Live Photo 视频一同移入应用回收站，
并可在图库恢复。人物页已可建立和裁剪脸部样本，尚未运行全库人脸扫描。

人物识别、疑似截屏／模糊照片筛选、短时间相似照片分组的执行顺序、审核边界和验收标准见
[`PHOTO_REVIEW_ROADMAP.md`](PHOTO_REVIEW_ROADMAP.md)。样本库准备好并经小批预演前，
不启动全库高负载扫描；未扫描项目不能标记为“没有人物”。

- 缩略图和视频封面长期存放在 S300 的独立缓存目录，不混入原片目录；扫描器必须排除该目录。
  第一版按需生成、限制并发，不在启用浏览器时一次性处理整库。网格缩略图建议长边约 384
  像素，具体编码和容量以实测为准。缓存可以重建，绝不作为唯一数据来源。
- 缓存项需要与稳定的媒体标识关联，不能仅以当前路径命名。整理移动原片后，同一个媒体标识
  仍指向新路径，已生成的缩略图继续可用；实现前需为现有索引补充或迁移这种稳定标识。
- 生成完成后先写临时文件、核对成功再原子改名。缓存目录沿用家庭影像的访问权限，浏览接口
  只允许访问索引内的媒体，不接受任意文件路径。原片离线或缓存损坏时显示可重试状态，
  不因此修改索引或原片。
- 视频列表先显示单帧封面、时长和大小；点击后才按需读取并播放原视频，支持分段请求和拖动。
  仅对当前设备无法播放的格式按需生成临时兼容版本，不预先转码或复制全部视频。

## 待确认时间的线索恢复与年份归档

第二轮先按证据可支持的精度归档：月份一致的进入 `家庭影像库/YYYY/YYYY-MM/`；
只能确定年份的进入 `家庭影像库/YYYY/_仅确定年份/`；年份冲突或未知的进入
`家庭影像库/未能归档，未归类/`，保留原相对路径供人工审核。月份或年份目录不代表
已确认具体拍摄日，不得填入虚构月日，也不给文件名加虚构时间前缀。

另有 2,548 项被标为内嵌时间，其中 2,547 项显示 1899 年，必须作为异常值排除。
在“仅文件修改时间”组里，1,022 个文件名符合 `YYMMDD_HHMMSS` 且日期有效。
