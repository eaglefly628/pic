## 1. 产品概述

一款**面向家庭的私人理财与机密信息管理桌面软件**。集中、安全地记录家里所有资金的存放情况与变化历史，并作为家庭的"机密保险箱"统一保管所有密码与个人常用信息。所有数据本地加密保存，强调**隐私、安全、简单易用**。

### 1.1 解决的核心问题
- 家里资金分散在多个账户/机构/形式（银行、现金、支付平台、理财、房产等），缺乏一个统一、能看趋势的总账。
- 各类密码、证件、卡号、重要号码散落各处，不安全也不好找。
- 既有的历史记录（Excel 表格）需要被沉淀为可持续更新、可视化的历史数据。

### 1.2 产品定位与关键约束（已确认）
| 维度 | 决策 | 含义 |
|---|---|---|
| 平台形态 | **桌面软件（Windows / macOS）** | 设计以桌面为主，窗口式布局；非移动端 |
| 数据存储 | **纯本地** | 数据只存在本机，**不联网、不上传任何服务器**；无账号注册、无云同步 |
| 使用者 / 登录 | **单一主密码（全家共用金库）** | 一个主密码解锁全部内容；无需多账号、无需权限分级 |
| 界面语言 | 中文优先（可预留多语言） | |
| 第一性原则 | **安全 > 简单 > 美观** | 面向非技术家庭成员也能上手 |

### 1.3 目标用户
- 家庭管理者（记录、维护数据的人）。
- 家庭成员（查看资产概况、查找密码/信息）。
- 全员通过**同一个主密码**进入，软件内不区分账号与权限。

## 2. 设计基调（给设计工具的说明）

- **形态**：桌面应用，建议左侧主导航 + 右侧内容区的经典三栏/两栏布局，适配桌面大屏与中等窗口。
- **气质**：克制、专业、有"安全感与信任感"；不浮夸。可参考密码管理器（如 1Password、Bitwarden）+ 记账/净资产看板（如 Monarch、Copilot）的结合。
- **主题**：支持**深色 / 浅色**两套主题。
- **信息密度**：中等偏高（资金与条目类数据多），但要清晰分组、留白合理。
- **安全可见性**：敏感字段默认**遮蔽（••••）**，需点击"显示"或悬停才可见；提供"一键锁定"。
- **语言**：全中文文案；数字、货币需本地化格式（千分位、币种符号）。
- **可访问性**：足够的对比度、可调字号、键盘可达。

## 3. 角色与典型场景（User Stories）

- 作为家庭管理者，我希望**录入并定期更新各账户余额**，这样我能看到家里总资产随时间的变化。
- 作为家庭管理者，我希望**把过去的 Excel 历史记录导入**进来，作为历史数据的起点。
- 作为家庭成员，我希望**一眼看到家里现在有多少钱、都放在哪里**。
- 作为任意成员，我希望**快速找到某个网站/银行的密码**并安全地复制使用。
- 作为任意成员，我希望**保存身份证、银行卡、WiFi、保险单等常用信息**，随用随查。
- 作为用户，我希望软件**离开就自动锁定**，且即使电脑丢失，数据也无法被破解。

## 5. 功能模块详述

### 5.1 首次启动 / 创建主密码（Onboarding）
- 欢迎页 → 创建主密码（输入两次）→ 显示**密码强度**与建议 → 强提示「**主密码无法找回，丢失=数据永久无法解密**」→ 提示设置/导出**恢复备份**。
- 可选：生成并展示一段**应急恢复信息**（如恢复密钥/助记，供用户离线妥善保管）。
- 完成后进入空状态仪表盘，引导用户「导入历史数据」或「添加第一个账户」。

### 5.2 解锁 / 锁定（Unlock & Lock）
- **解锁页**：输入主密码 → 解密进入。错误有节流/延迟，防暴力尝试。
- **自动锁定**：闲置超时（默认可设 1/5/15 分钟）、最小化或锁屏时自动锁定。
- **手动锁定**：顶部一键锁定。
- 锁定时所有内容从界面与内存中清除/遮蔽。
- 可选（后续）：**生物识别快捷解锁**（Touch ID / Windows Hello）作为主密码的便捷补充。

### 5.3 仪表盘（数据预览 / Dashboard）
核心看板，回答"家里现在的钱怎么样"：
- **关键指标卡**：总资产、总负债、**净资产**，以及较上一期的变化（金额 + 百分比 + 涨跌色）。
- **资产趋势图**：净资产 / 总资产随时间的折线图（来自历史快照），可切换时间范围（近 3 月 / 1 年 / 全部）。
- **资产构成图**：饼图/环形图，可按**类型**（银行/现金/理财/房产…）、按**机构**、按**归属人**切换。
- **最近更新**：最近录入/变动的账户列表。
- **提醒区**（后续可选）：证件即将到期、某账户长期未更新、密码长期未修改等。
- 空状态：引导导入或新增。

### 5.4 资金管理（账户与余额历史）
**账户列表**：卡片或表格，显示名称、类型、机构、归属人、当前余额、币种、占比；可分组、排序、筛选、搜索。

**账户字段（数据模型见 §6）**：名称、类型、机构、币种、当前余额、归属成员、卡号末四位（敏感）、备注、状态（活跃/已销户）。

**账户类型（建议枚举，可扩展）**：储蓄/活期、定期、现金、支付宝、微信、证券/股票、基金、理财产品、外币、贵金属、房产、车辆、应收/借出款、**负债/借款**（计为负值）、其他。

**余额历史（快照）**：
- 这是历史数据的核心——按时间点记录各账户余额，形成"净资产随时间变化"。
- **账户详情页**：展示该账户余额随时间的折线/列表，可新增一条新的"余额快照"（日期 + 金额 + 备注）。
- 支持"批量记账日"：选择一个日期，一次性更新多个账户余额（常见的"月末盘点"工作流）。
- （后续可选）除"余额快照"外，支持"收支流水"明细记账——**待 §12 确认是否需要**。

**新增/编辑账户**：表单弹窗或侧滑面板。

### 5.5 历史数据导入（Excel）
将既有 Excel 历史记录导入为历史快照数据：
- 选择文件（支持 **.xlsx / .xls / .csv**）。
- **预览**原始表格内容。
- **字段映射**：把表格列映射到系统字段（日期、账户/科目、金额、币种、备注、归属人…），支持记忆映射模板。
- **校验与纠错**：日期/金额格式校验、缺失项提示、重复检测。
- **导入结果**：成功/跳过/失败条数与明细，可回滚本次导入。
- 导入后数据立即体现在仪表盘趋势中。
- ⚠️ **依赖项**：导入的字段与映射规则需依据**你提供的 Excel 样本**最终确定（见 §12）。

### 5.6 密码保险箱（Password Vault）
- **条目列表**：按分类/标签分组，支持搜索、收藏、最近使用。
- **条目字段**：名称、网址、用户名、**密码（默认遮蔽）**、分类、标签、备注、（可选）两步验证 TOTP、（可选）附件、创建/修改时间、最后使用时间。
- **交互**：
  - 一键复制用户名/密码，复制后**自动在 N 秒后清空剪贴板**（默认 30s，可设）。
  - 显示/隐藏密码切换。
  - **密码生成器**（长度、大小写、数字、符号、易读模式），可一键填入。
  - **密码强度**指示；可标记"弱/重复/久未更换"的密码（后续）。
- **分类示例**：网站账号、银行/支付、邮箱、社交、工作、WiFi、设备、其他。

### 5.7 个人常用信息（机密信息）
保存结构化的家庭常用机密信息，每类有合适的字段模板：
- **类型示例**：身份证、护照、银行卡、社保/医保卡、驾驶证、行驶证、保险单、会员卡、WiFi、紧急联系人、重要电话号码、其他自定义。
- **通用字段**：标题、类型、归属成员、各类型专属字段、备注、**附件（如证件照片，加密存储）**、自定义字段。
- 列表可按类型/成员筛选与搜索；敏感字段默认遮蔽。

### 5.8 全局搜索
- 解锁状态下，跨模块搜索（账户、密码、个人信息）。
- 结果按模块分组，点击直达详情。

### 5.9 设置
- **安全**：修改主密码、自动锁定时长、剪贴板清空时长、（可选）生物识别开关。
- **备份与恢复**：见 §5.10。
- **外观**：深/浅色主题、字号。
- **数据**：货币与默认币种、归属成员（家庭成员名单维护，仅用于归类，非登录账号）、导入映射模板管理。
- **关于**：版本、许可、数据存储位置说明、安全说明。

### 5.10 备份与恢复
- **导出加密备份**：生成单个**仍为加密**的备份文件（如 `.vault`），可存到 U 盘/移动硬盘。备份用主密码（或独立备份口令）保护。
- **从备份恢复**：选择备份文件 + 输入口令 → 还原数据。
- 提示用户定期备份；纯本地无云，**备份是唯一的灾难恢复手段**。

## 6. 数据模型（概要）

> 实体与主要字段，供设计字段与后续建库参考。所有敏感字段加密存储。

**FamilyMember（家庭成员，用于归类）**：id、姓名、备注。

**Account（账户）**：id、名称、类型、机构、币种、当前余额、归属成员、卡号末四位(敏感)、备注、状态、创建/更新时间。

**BalanceSnapshot（余额快照）**：id、账户id、日期、金额、备注、来源（手动/导入）。

**（可选）Transaction（收支流水）**：id、账户id、日期、金额、收/支、分类、备注 —— *待确认是否纳入。*

**PasswordItem（密码条目）**：id、名称、网址、用户名、密码(敏感)、分类、标签[]、TOTP(敏感,可选)、备注、附件[]、收藏、创建/更新/最后使用时间。

**InfoItem（个人信息条目）**：id、标题、类型、归属成员、字段集合(敏感)、附件[]、备注、创建/更新时间。

**ImportTemplate（导入映射模板）**：id、名称、列→字段映射规则。

**Settings**：主密码校验材料(KDF 盐+参数+加密的数据密钥)、自动锁定时长、剪贴板清空时长、主题、默认币种等。

## 7. 安全与加密需求（核心）

> 用户明确要求"很好的加密算法"。以下为推荐方案，目标：**即使整台电脑/数据文件被他人获取，没有主密码也无法解密**。

### 7.1 加密总体架构（信封加密）
1. 用户**主密码**经过**密钥派生函数**生成"主密钥"。
   - 推荐 **Argon2id**（内存硬、抗 GPU 暴力破解）；参数示例：内存 64–256 MB、迭代数与并行度按设备调优。
   - 备选：PBKDF2-HMAC-SHA256，迭代次数 ≥ 600,000。
   - 每个金库使用唯一随机 **盐（salt）**。
2. 随机生成一个 256-bit 的**数据密钥（DEK）**，真正用于加密数据；主密钥只用来加密/解密这个 DEK（信封加密）。
   - 好处：改主密码只需重新加密 DEK，无需重新加密全部数据。
3. **数据加密算法**：**AES-256-GCM**（带认证，硬件加速）；或 **XChaCha20-Poly1305**（随机 nonce 更友好）。
   - 每次加密使用**唯一 nonce/IV**，并存储认证标签（防篡改）。
4. **主密码绝不明文存储**；只存储：KDF 盐与参数、被主密钥加密后的 DEK、密文与认证标签。
5. **静态存储**：建议使用 **SQLCipher（AES-256 加密的 SQLite）** 作为本地库，或采用"单一加密文件，运行时解密入内存"的方案。

### 7.2 运行期安全
- **自动锁定**：闲置超时、最小化/系统锁屏时锁定，清空界面与内存中的明文。
- **剪贴板**：复制敏感内容后定时自动清空（默认 30s）。
- **暴力破解防护**：解锁失败递增延迟。
- **内存**：尽量减少明文驻留时间，锁定/退出时尽力清理（best-effort）。
- **完全离线**：除用户主动选择的导入/导出文件操作外，**不发起任何网络请求**，无遥测、无云。
- 可选：防截屏/隐私模式、应用内查看附件而非落盘解密。

### 7.3 备份安全
- 备份文件保持加密；可用主密码或独立的备份口令保护。

## 9. 非功能需求

- **平台**：Windows 10+ 与 macOS（桌面窗口应用）。
- **性能**：家庭级数据量（账户数十、历史快照数千、密码/信息条目数百）下，操作流畅、解密快速。
- **可用性**：面向非技术家庭成员，关键流程 ≤ 3 步；中文文案清晰友好。
- **可靠性**：本地数据不丢失；写入有事务保障；提供备份机制。
- **可移植**：数据可通过加密备份在多台个人设备间手动迁移（非自动同步）。
- **隐私**：无账号、无追踪、无网络外发。

## 10. 技术实现建议（可选，仅供参考，不约束设计）

- **桌面框架**：**Tauri**（Rust 后端 + Web 前端，体积小、内存安全、适合本地加密）为首选；或 Electron（生态成熟，可较多复用已有 React/Next.js 经验）。
- **前端**：React + TypeScript（Tauri 下可用 Vite；Electron 同理）。可复用此前项目的 React/Tailwind 经验。
- **本地存储**：SQLCipher（加密 SQLite）或加密文件 + 内存数据库。
- **加密库**：成熟实现的 Argon2id、AES-256-GCM / XChaCha20-Poly1305（避免自研密码学）。
- **Excel 解析**：成熟的 xlsx 解析库。

## 12. 待确认事项（Open Questions）

1. **Excel 样本**：请提供历史记录的 Excel 文件（或脱敏样例），用于最终确定**导入字段、列映射规则与数据模型**。这是把历史数据接进来的关键。
2. **记账粒度**：资金部分只需要"**余额快照**"（定期盘点各账户余额），还是也需要"**收支流水**"明细记账？
3. **多币种**：是否涉及多种货币、是否需要汇率换算与统一折算？
4. **生物识别解锁**：是否希望在主密码之外，支持 Touch ID / Windows Hello 快捷解锁？
5. **产品名称**：确认正式名称（当前暂用"家庭金库 / Family Vault"）。
6. **附件**：个人信息/密码是否需要存证件照片等附件（影响存储与加密设计）。
