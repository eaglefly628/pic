## 一、这个 app 现在的问题

不是"不好看"。是**做了 24 个界面，但每个界面像是分几次做的，规则没对齐**。

具体到能指出来的：

### 1. 表格系统没有统一规则（最扎眼）

24 屏里有 9 张表/列表，规则完全各行其是：

- **只有 4 张有表头行**：余额快照、利息预测、收入、（部分）。
  而**预算页的开销列表列宽节奏几乎一模一样（90/110/130/70），却没有表头** —— 同一个 app 里两张长得几乎一样的表，一张有表头一张没有。
- **只有 1 张表有合计行**（利息预测）。收入、开销的合计被塞进了上方的指标卡里。两套做法并存，用户得学两遍。
- **零状态覆盖不全**：收入、开销、密码、信息、备份、利息都写了空态文案，但**资金账户列表和余额快照没有** —— 零数据时就是一片空白，看着像坏了。
- **密码列表的分类列会塌陷** —— 没填分类时那一列整个不渲染，同一张表里各行的列位置对不齐。

### 2. 删除行为不统一，而且危险的那个反而没确认

| 操作 | 现在的行为 |
|---|---|
| 删余额快照 | 二次确认 ✅ |
| 删收入 / 开销 / 密码 / 个人信息 | **点了就删，没有确认** ❌ |
| 设置里删备份 / 恢复备份 | 二次确认 ✅ |
| **导入 Excel（会替换全部账户和快照）** | **没有确认** ❌❌ 最危险的操作反而最没保护 |

### 3. 排序能力分布很散

账户列表有 3 种排序可切（按分类 / 全部排序 / 按更新时间，见 03/04/05 三张截图）；
利息、最近更新、资产构成是写死的排序；
收入和开销**就是数组插入顺序** —— 条目一多就没法整理。

### 4. 密度和节奏不稳

同一个 1200×800 的窗口里，有的页面（仪表盘、资金账户）信息塞得很满，
有的页面（导入导出、设置、密码空态）大片留白，
卡片内边距、卡片间距、区块标题的处理各页不一致。

### 5. 隐藏区（独立管理）像另一个 app

`20`–`24` 五张截图是隐藏区。它自己有一套导航、一套卡片样式、一套配色浓度，
跟主应用只是"大概像"，不是"同一套系统"。

## 二、硬性约束（这些不许改，改了就不能用）

| 约束 | 说明 |
|---|---|
| **窗口尺寸固定 1200×800** | 整个 app 是一个居中的固定尺寸"窗口"，外面是渐变壁纸。不是响应式网页，别做移动端断点。窗口内左侧栏 236px + 顶部工具条 52px 是现有骨架 |
| **深浅双主题都要做** | 通过 `.fv-root[data-theme="light"|"dark"]` 上的 CSS 变量切换。任何新增颜色都必须两套都给，不许只在一个主题里能看 |
| **纯中文界面** | 所有文案中文。字体栈第一位是 `-apple-system` / `PingFang SC`，主人用 Mac |
| **完全离线** | 不许引 CDN、Google Fonts、远程图标库、外部 CSS。所有资源本地化。唯一联网的是财经行情页抓行情，那是业务功能 |
| **技术栈不换** | React 18 + TypeScript + Vite。不许引入 Tailwind / MUI / Ant Design / shadcn 等 UI 框架 —— 这是本地个人项目，不背依赖 |
| **金额必须等宽对齐** | 所有数字列用 `font-variant-numeric: tabular-nums`。负号是 U+2212 `−`，不是 hyphen。现有 `lib/format.ts` 的格式化函数不许改输出格式 |
| **`prefers-reduced-motion` 要继续尊重** | 现有 `styles.css` 末尾已经写好了整套降级，新增动效必须补进去 |
| **无障碍不许倒退** | 现有已有 `:focus-visible` 描边环、键盘可达。改完要一样能用键盘走完 |

## 三、方向 A 具体要你做到什么

### 定一套令牌，然后全站只用令牌

现在 24 个界面的样式**几乎全是 inline style 里的魔法数字**（`fontSize: 13.5`、`padding: "7px 10px"`、`borderRadius: 9`……）。
第一步是把它们收敛成一套变量，写进 `styles.css`，然后各屏引用。

至少要覆盖：字号阶梯、行高、间距阶梯（4px 基准）、圆角阶梯、阴影层级、边框粗细。
现有值见 `03-现有设计令牌.md` —— **以那份为起点做收敛，不是推倒重来**。

现有的圆角就有 `6 / 7 / 8 / 9 / 13 / 14` 六档，字号有 `10.5 / 11 / 11.5 / 12 / 12.5 / 13 / 13.5 / 14 / 15` 九档。
这种量级的碎片化本身就是要解决的问题。

### 表格统一成一个组件

九张表统一成同一套：表头行要不要（建议全都要）、列宽怎么定、数字右对齐文字左对齐、
行高统一、hover 高亮统一、合计行统一放表底、空态统一。

### 密度往上提一档，但别挤

这是每天要扫一眼的工具，不是展示页。现在有些页面留白偏奢侈。
但注意：**这是家用理财，不是交易终端** —— 别做成 Bloomberg 那种极限密度，
主人不是坐在六屏前面的量化。舒服地多看到一两行就够了。

### 收敛动效

现有动效不少：壁纸 28 秒缓慢流动、卡片入场上浮、折线描线、环形图画出、
柱状生长、"此刻"点脉冲、渐变卡片流光、图标 hover 旋转、侧栏高亮滑行。
**保留有信息量的（描线、生长、侧栏滑行），砍掉纯装饰的（流光、图标旋转）。**
交互反馈类动画统一 ≤150ms，入场类 ≤550ms。

### 隐藏区并入主设计系统

`20`–`24` 那五屏要用跟主应用同一套令牌和组件，只靠配色浓度或一条顶部标识区分"你在隐藏区"，
而不是长得像另一个软件。

## 五、允许你改的 8 处交互不一致

按值不值得动手排序，做到几条算几条，做不动的在交付说明里写清楚：

1. 给所有表加统一表头行（尤其是预算页的开销列表）
2. 合计行的位置统一（建议：表底合计行，指标卡不再重复承担合计职责）
3. **删除行为统一**：所有破坏性操作都二次确认，**Excel 导入替换全部数据必须加确认**
4. 补齐空态：资金账户列表、余额快照
5. 利息表合计行的颜色规则跟它自己的数据行对齐（数据行有"零值显示灰色"，合计行没有）
6. 修 `来源` 列恒为「导入」的问题（`compute.ts:354` 三元的两个分支写成了一样，手动新增的快照被误标）
7. 修密码列表分类列塌陷（没填分类时整列不渲染，行与行对不齐）
8. 给收入、开销列表加排序（现在是数组插入顺序）

> 第 6 条虽然在 `compute.ts` 里，但它是一行显式的 bug，顺手修掉，不算"动数据逻辑"。
